# ADR 0003: legacy store snapshot and archive boundary

Status: package interface ready; production upgrade blocked, 2026-09-27.

The inherited `MusesSchema.current` is an unversioned SwiftData autoschema in the app target. It has 19 models. `CatalogRelease` and `CatalogArtist` are rebuildable Innertube caches; the other 17 models carry user state or sync intent. The package cannot instantiate the old SwiftData model graph because those classes belong to the app target and include app-only dependencies. Copying a subset of them into this package would risk SwiftData opening and migrating the source against a different schema.

`LegacyStoreSnapshotter.snapshot(sourceURL:destinationURL:)` opens the source SQLite database read-only, backs up its committed state including WAL pages, and runs `quick_check` on the copy. The app-side reader must open only that copy with the exact inherited model graph, fetch every model, and build `LegacyCompleteBundle`. The original database and WAL/SHM remain together for rollback. A failed snapshot, fetch, decode, inventory check, or import must show recovery and leave the original as authoritative.

`LegacyCompleteBundle` contains:

- A full 30-scalar `LegacyTrackArchive` per track. The public `Track` is a six-field playable projection; the archive retains album, artwork, lyrics and offset, catalog links, media kind, quality/codec, availability, timestamps, counts, and favorite status.
- The exact persisted `QueueState` scalar fields and its four JSON arrays. The playable projection retains current, up-next, future and history occurrences, repeat/shuffle and position, always paused. Raw queue JSON retains `locked`, priority, group, source context, historical state and rich track snapshots which the public queue contract cannot express. Unknown or malformed queue entries fail import.
- A `LegacyModelArchive` for every row of the other 15 user-state models. Its JSON object must include every declared scalar and relationship key, including explicit nulls. Relationships are encoded as stable referenced IDs, not live SwiftData objects. Full fields of notes, bookmarks, playlists, imports and listening events coexist with simpler public query projections. Sessions, inbox, EQ presets, automation/focus, playlist revisions and sync plans remain archives until public features can consume them.
- `LegacySetting` rows for present UserDefaults values, plus an inventory confirming all 52 known setting keys were checked. Values are preserved as data and are not automatically applied to the public app. Sensitive old cookie paths and consent switches need a product review before reuse.

The package validates its 19-model inventory, known settings inventory, archive field lists, projection IDs and queue data before writing. It rejects a nonempty target, writes records and a SHA-256 receipt in a SwiftData transaction, and accepts the same bundle again only when its canonical payload digest matches. It does not replace corrupt target records or import over public edits. The old source store is never modified by this package.

The tests cover WAL snapshotting, corrupt SQLite input, disk reopening, archive fidelity, queue projection, validation rejection and idempotence. They use a representative JSON field fixture and a small SQLite fixture, **not a database created by the inherited 19-model SwiftData schema**. The upgrade gate therefore remains blocked. Integration must generate a physical fixture with the app's exact old `MusesSchema.current`, including relationship cycles, nonempty queue JSON, settings, and WAL; run the app-side reader against it; compare all IDs and archived fields; then test opening that same fixture in the previous app version after a failed and a successful migration. The public app must keep its existing recovery screen until that work passes.
