## Composition and signing

Public distribution must use `project-public.yml`. It includes the shared project spec and explicitly replaces dependencies to omit YouTubeKit. Generate with:

```sh
mkdir -p .artifacts/public-project
xcodegen generate --spec project-public.yml --project .artifacts/public-project --project-root .
```

Archive `.artifacts/public-project/MusesPublic.xcodeproj`, scheme Muses, Release. The app Info.plist resolves from the repository source root. No native resolver/MPRemoteCommandCenter, private browse endpoint, background modes or DEBUG fixtures appear in the audited public binary. `ExperimentalNativePlayback` is a disabled stub in this composition. The first initial public archive failed the private-endpoint audit because the base project's package dependency still linked YouTubeKit; it was replaced by the explicit public composition before publication.

Native distribution uses the base `Muses.xcodeproj`, scheme Muses, Native. Its real engine is behind MUSES_NATIVE_PLAYBACK; background audio is declared and the user must enable experimental playback. Research Home browse code and DEBUG fixture controls are excluded from both distribution configurations. CFBundleVersion and CFBundleShortVersionString use project settings.

Signed public export method: app-store-connect. Signed native export method: release-testing (Ad Hoc), 1 registered device. Both use Apple Distribution, get-task-allow=false, team/bundle identity checks and strict nested codesign verification. No private signing keys or raw account credentials are release assets. The Native Ad Hoc package requires compatible device registration or re-signing; the Public App Store package is an upload artifact, not an Ad Hoc installer.
