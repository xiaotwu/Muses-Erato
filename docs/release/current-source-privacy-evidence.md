### Content status: Made For Kids remains unimplemented/unverified

Source tracing, not only a string search, found that `YouTubeDataCatalog.videos` requests `part=snippet`; `CatalogItem`/`DataItem` have no video `status.madeForKids` mapping. This does not establish what the remote YouTube player itself does.

The [video resource reference](https://developers.google.com/youtube/v3/docs/videos#status.madeForKids) documents the status field. **CONTENT-STATUS is open:** establish supported handling for known/unknown status across direct links, imports, queue and restart, its effective data-processing controls, and applicable audience/child-directed designation. No implementation was added here, and source strings, successful playback or normal OAuth consent do not close this gate. Provider/platform clarification may be needed for the chosen integration; this document does not invent an unsupported player parameter or issue a general legal-compliance verdict.

## 4. Deletion, caches, tokens and retry semantics

**Single item/category:** [LocalLibraryDeletion.swift](../../Packages/MusesPersistence/Sources/MusesPersistence/LocalLibraryDeletion.swift) stages active graph changes and note/bookmark cleanup in one save with rollback. Session state changes only after success. Songs targets the playlist-membership union. These operations preserve historical archives. Coverage: [LocalLibraryDeletionTests.swift](../../Packages/MusesPersistence/Tests/MusesPersistenceTests/LocalLibraryDeletionTests.swift), `testSingleCommitCleansEntirePublicGraphAndPreservesArchive` and `testSaveFailureRollsBackAllStagedMutations`; [PublicYouTubeFlowTests.swift](../../Tests/MusesTests/PublicYouTubeFlowTests.swift), `testDeleteCurrentVideoCleansReferencesAndSurvivesRelaunch`, `testFailedDeletionDoesNotPublishSuccessOrDismissCurrent`, `testBatchClearScopeAndRestart`; [PublicPlaylistImportTests.swift](../../Tests/MusesTests/PublicPlaylistImportTests.swift), `testSongsClearRemovesOnlyPlaylistUnionAndRetainsUnlistedSavedVideo`.

**Sign-out/revoke:** `PublicYouTubeSession.signOut` advances the account epoch, resets account display pages, force-expires display metadata and invokes `OAuthClient.revokeAndDelete`. [OAuth.swift](../../Platform/iOS/OAuth/Sources/MusesIOSOAuth/OAuth.swift) attempts token-store deletion and private-cache cleanup even if remote revocation or token loading fails; storage failure is distinct from remote failure. Tokens use `AfterFirstUnlockThisDeviceOnly` Keychain. The injected `PublicPrivateData` clears the private Catalog cache; sign-out is not whole-library or WebKit erasure. Google browser/system authentication storage is a separate boundary.

Coverage: [OAuthTests.swift](../../Platform/iOS/OAuth/Tests/MusesIOSOAuthTests/OAuthTests.swift), `testTokenStoreFailuresStillAttemptPrivateCacheDeletion`, `testExchangeAndRevokeDeletesPrivateData`, `testFailedRemoteRevocationStillDeletesLocalData`. Those tests cover explicit deletion/revoke methods. They do not cover every revoked-refresh fault: the `accessToken` invalid-grant catch currently calls `store.delete()` before `deletePrivateData()` without the all-attempts aggregation used by explicit deletion; a throwing first call can skip the latter. Sign-out also has no equivalent of the full-wipe durable tombstone. Record hardware/locked-Keychain and restart behavior before claiming universal revocation cleanup.

**Full local-data deletion:** `PublicYouTubeSession.deleteLocalData`/`finishRecordedDeletion` and the router implement the following sequence:

1. Detach the player, invalidate account work, cancel sign-in, and durably record deletion intent before asynchronous cleanup. Best-effort immediate row erasure is not the success criterion.
2. Remove visible/repository references; attempt local OAuth cleanup, all Catalog-cache clearing, website/cache cleanup, a bounded wait for tracked network operations, then direct deletion of both current and inherited Keychain service entries through [PublicCredentialDeletion.swift](../../Sources/Muses/App/PublicCredentialDeletion.swift). Failures are accumulated and leave the pending screen/marker in place.
3. [PublicWebsiteDataDeletion.swift](../../Sources/Muses/App/PublicWebsiteDataDeletion.swift) cancels shared URLSession tasks, verifies their completion, clears shared URLCache/cookies, removes and rechecks all data types in the app's default WebKit store, removes the owned legacy `Caches/Muses` directory, then clears shared cache/cookies again. It does not erase Safari/ASWebAuthenticationSession's profile.
4. Only successful external cleanup sets `externalCleanupComplete`. The deletion route supersedes migration/successor pointers. A fresh process unlinks original/default SQLite main/WAL/SHM and old UUID upgrade directories, removes obsolete active/pending pointers, and initializes or validates the new deletion generation. The originating process may return an empty usable generation while **retained-file cleanup still explicitly requires restart**. It must not be described as already physically complete.

Coverage: [PublicUpgradeStartupTests.swift](../../Tests/MusesTests/PublicUpgradeStartupTests.swift), `testPhysicalLegacyStartupRelaunchAndExplicitDeletion`, `testFailedCredentialCleanupStillAttemptsWebsiteCleanupAndRestartsPending`; the latter injects credential failure, verifies website cleanup still runs and the marker stays incomplete, then creates a new session with successful seams. `PublicWebsiteCleanupTests.testWebsiteCookieAndFoundationCacheAreRemoved` uses a synthetic isolated WebKit store and cookie, Foundation cache, and legacy-cache directory while retaining an unrelated file. Process harness evidence adds genuine process termination at documented migration/deletion boundaries. A test named “PhysicalLegacy” concerns a file-backed legacy store; it is not proof of physical-iPhone Keychain or Google-cookie erasure.

Remaining validation must address real locked/protected files and Keychain, interrupted website cleanup, all in-flight refresh/import paths and late writes, restart completion and external backups. The full-wipe route is durable and tested at specified seams; no claim of forensic flash erasure, universal late-callback coverage, remote Google revocation by `deleteLocalAccount`, or deletion of uncontrollable copies follows.
